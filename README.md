# GFAM - 少女全自动 / Girl Fully Automatic

GFAM 是一个面向《少女前线》相关自动化流程的个人项目，提供 Tkinter 图形界面与菜单式命令行双入口，整合 9 大功能模块、跟随制造系统、跨进程协调、运行状态仪表盘、本地缓存与环境检查脚本。

> v1.2 正式发布版不包含真实 UID、SIGN、Index/index 原始响应、运行缓存、抓包文件或个人账号数据。

## 功能概览

### GUI 图形化启动器

- 基于 Tkinter 的完整图形界面，PyInstaller 打包为独立可执行文件。
- 服务器选择、UID/SIGN 获取、模块启动、日志渲染一站式操作。
- ANSI 彩色日志实时渲染，运行状态一目了然。
- 模块运行结束后自动弹出统计摘要窗口。

### 主菜单与基础能力

- 服务器选择：SOP、RO635、M4A1、M16、AR-15、EN。
- UID/SIGN 获取：通过内置代理自动拦截游戏登录流量，功能模块沿用会话信息。
- Windows 环境检查：检测 Node.js、Python、内置 gflzirc，并给出中文提示。
- 模块化菜单：各模块独立接管命令行，退出后返回 GFAM 主菜单。
- 运行状态仪表盘：主要模块提供固定下方状态面板，显示当前关卡、轮次、仓库、进度、掉落与停止方式。
- 运行摘要弹窗：各模块结束后自动生成 JSON 摘要并在 GUI 中弹出统计窗口。
- 妖精自动：可在主菜单开启妖精自动建造 / 领取 / 强化，并在支持模块中显示妖精自动状态。

### EPA 打捞

- EPA 普通 / 紧急 / 夜战打捞流程。
- 单人打捞模式与满级停机设置。
- 人形与装备掉落统计。
- 夜战专属装备目标统计与自动上锁保护。
- 人形仓库与装备仓库本地估算。
- 仓库不足时的应急拆解与运行结束收尾拆解。
- 支持跟随模块制造（后台人形/装备制造）。

### 13-4

- 13-4 五战练级。
- 13-4 双单人五战四项基础资源打捞。
- 固定双梯队路线与移动梯队显示。
- 运行结束统计四项资源变化。
- 人形掉落拆解与仓库保护。

### A-10 四项资源获取

- 基于 EPA 普通 A-10 的单人不移动四项资源获取方案。
- 只部署第一梯队，要求第一梯队为单人梯队。
- 不移动、不 battleFinish，直接结束回合并结算。
- 运行前和运行结束各请求一次 Index/index，用于队伍校验与四项资源统计。
- 运行中使用本地仓库空位缓存与 pending 掉落队列，仓库缓存不足或运行结束时批量拆解。
- 受限于每轮结算需要多个请求响应交互，最高速率约为 1 结算/秒。

### 获取训练资料 / 自动训练

- 获取训练资料。
- 自动训练与自动循环入口。
- 本地 Index/cache 优先策略，减少重复请求。
- 自动训练队列按既定规则处理候选对象。

### 零元购

- f2p 零元购。
- f2p_pr 零元购 PR（额外核心）。
- 基于零元购结算掉落的人形仓库估算。
- 本轮掉落拆解与运行结束收尾拆解。

### 教练の妙妙小巧思 / 一键打捞

- 人形一键打捞计划。
- 装备一键打捞计划。
- EPA 夜战专属装备路线规划。
- 目标装备统计、自动上锁保护、装备拆解过滤。
- 装备仓库可安全轮数估算与应急拆解。

### 制造自动化

- 后台人形制造：5 种公式（手枪/冲锋枪/步枪/突击步枪/机枪），支持保护模式（保留目标、全部拆解、保留五星）。
- 后台装备制造：18 种装备公式，支持自动保护五星与自定义保护列表。
- 作为独立后台进程运行，可与打捞/资源模块并行。
- 通过拆解锁与 A-10 协调拆解操作，避免仓库冲突。

### 灰域自动彩蛋

- 灰域彩蛋地图重置与彩蛋任务识别。
- MOVE / BATTLE 彩蛋路线执行。
- BuildingSkillPerformOnDeath 接口支持。
- 正式运行前请求一次 Index/index 写入基准。
- 探查许可证、四项资源、当前灰域积分、当前轮次本地缓存。
- 四项模式下优先消耗探查许可证：1 张探查许可证等价于四项各 10，不足部分补扣四项。
- 当前进度显示：`xxxx/6000（本次运行已完成 x 轮）`。
- 探查许可证 item_id：`10702`。
- 彩蛋积分 item_id：`10736`。
- startMission 短明文响应重试。
- `abortMission` 卡关清理：支持 `-abort` 手动退出当前灰域关卡，并在运行前/异常时尝试清理旧灰域状态。
- 灰域专用固定下方仪表盘与妖精自动状态显示。

### 跨进程协调

GFAM 运行时最多产生 4 个独立 OS 进程（主模块 + 妖精后台 + 制造后台 + 认证捕获），通过以下机制安全协调：

- **全局 API 锁**：序列化所有 GFL 服务器请求，防止并发冲突。
- **拆解锁**：专门序列化人形/装备拆解请求，A-10 与制造模块并行时互不干扰。
- **Index 缓存**：三级查找（内存 → 共享文件 → 网络），TTL 300 秒，减少重复请求。
- **仓库/妖精缓存**：后台进程写入状态，前台模块读取用于仓库估算和摘要统计。

## 运行环境

- Windows 10 / Windows 11
- Python 3.11+
- Node.js
- 内置 gflzirc 兼容组件

## 快速启动

### GUI 模式（推荐）

双击 `GFAM-GUI.exe` 或运行：

```bat
RUN_GFAM_GUI_FROM_DIST.bat
```

### 命令行模式

双击或在命令行运行：

```bat
run_windows.bat
```

首次运行会进行环境检查。选择服务器后，按菜单提示获取 UID/SIGN，再进入对应功能模块。

## 常用命令

主菜单常用入口：

```text
1 / epa         EPA 打捞
2 / 13-4        13-4 五战练级 / 四项基础资源打捞
3 / a10-resource  A-10 单人不移动四项资源获取
4 / pick        获取训练资料 / 自动训练 / 自动循环
5 / f2p         零元购 f2p
6 / f2p_pr      零元购 PR（额外核心）
7 / smart       一键打捞计划 / 装备一键打捞
8 / factory     制造自动化设置（人形/装备后台制造）
9 / greyzone    灰域自动彩蛋
fairy           妖精自动建造 / 自动强化开关
auth            重新获取 UID/SIGN
server          切换服务器
0 / exit        退出
```

模块内常见停止命令：

```text
-q  当前 Macro / 当前任务后安全停止
-Q  当前 Micro 后安全停止（部分模块支持）
-E  返回 GFAM 主菜单
```

## GHA / Linux 运行入口

本包额外提供 GHA/Linux 入口，不依赖 Windows 批处理和 Node.js 主菜单。

```bash
cp examples/gha.env.example .env
# 编辑 .env 填写 GFAM_SERVER / GFAM_USER_UID / GFAM_SIGN_KEY
./run_gha.sh
```

也可以直接启动指定模块：

```bash
./run_gha.sh --module greyzone --server SOP
```

详细说明见 `docs/GHA_USAGE.md`。
